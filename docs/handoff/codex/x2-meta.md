- PR 验证工作流使用 Node 22 和 npm 缓存，依次执行单文件构建、无头测试和完整黄金快照检查。
- 接口、数据结构、损坏恢复和新增迁移的方法见 [META.md](../../META.md)。

## 决策

- 业务进度挂在 `ctx.profile`。解谜和守护在结算时分别调用 `recordPuzzleStars` 和 `recordDefenseRun`；文明和生态按模式名列出实际槽位。图鉴和反应监听既有世界事件。
- 自动保存默认关闭，启用后写入专用槽位。导出涵盖可恢复的新格式槽位和模式数据，导入在所有槽位及新格式清单校验成功后提交目录。
- 世界保存完整的序列化文本。沙盘复用 `exec('restoreFull')` 读取，C0 对种子和区域的处理差异已登记在 [API_REQUESTS.md](../../API_REQUESTS.md)。区域数据已用替身和公开反序列化接口核对。
- fake-indexeddb 只用于无头测试。单文件已检查内嵌模块和资源引用，不加载第三方脚本。

## 复查修复

- IndexedDB 将每次档案操作放进同一原生事务，多个标签页共享事务顺序。localStorage 在缺少 Web Locks 时按票号排队，暂停后失去票据的页面会中止旧操作。
- v4 槽位独立记录上一版 Blob。设置、发现事件和其他槽位写入后仍可回退。v3 双目录自动转换。旧档迁移按分区校验，从备份或默认值修复坏分区。
- 主、后备库同时有进度时合并到 IndexedDB。同名的不同世界各保留一份。迁移有接收记录，目录退役或清理中断可重试。
- 新备份校验完整槽位清单，缺项、改名或移除清单会拒绝导入。没有清单的旧文件按名称合并，本机独有槽位保留。档案格式和冲突规则见 [META.md](../../META.md)。

- 已用真实浏览器在 IndexedDB 保存带缩略图的沙盘槽位，导出 JSON 文件、删除槽位、导入文件并再次读取。
