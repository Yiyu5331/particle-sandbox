# 程序生成地图

从主菜单打开「地图生成器」，也可以直接访问 `dist/particle-sandbox.html?mapgen=1`。图册默认按种子展示全部群系；选择单个群系后可连续比较 12 个种子。选中缩略图即可看剖面、开关区域标记，或对该图运行 300 步物理检查。

## 在模式中使用

```js
import { generateMap } from './src/gen/index.js';
import { createWorld } from './src/engine/index.js';

const map = generateMap(42, {
  width: 422, height: 246, biome: 'archipelago',
  preset: 'defense', relief: 0.75, villageWidth: 36,
});
const { width, height, seed } = map.meta;
const world = createWorld({ width, height, seed });
for (const cmd of map.commands) world.exec(cmd);
const villageId = world.addRegion(map.regions.village);
const westVent = map.regions.spawns.left.lava;
world.step(300);
const recording = world.recording();
```

`generateMap` 是同步纯函数，返回可直接 JSON 序列化的 `{commands, regions, meta}`。在尺寸、种子相符的新世界执行命令，世界会照常录制。命令依次清空地形、设定重力和环境、铺设材料。横向相邻、材料和上下边界都相同的纵向游程合并为一个 fillRect。模式可自行选择要注册的区域及其保护规则。

| 参数 | 范围与缺省值 |
|---|---|
| seed | 必填整数，−2147483648～4294967295，统一为无符号 32 位。−1 与 4294967295 生成同图。 |
| width、height | 宽 64～1024，高 48～512，默认 160×96。最小尺寸为基岩、可用村台、湖泊和两侧坡道留出空间。 |
| biome | 默认 `grassland`。支持下表的八种取值。 |
| relief | 0～1，默认 0.65，四舍五入到千分位。0 表示最低自然起伏，河床、湖盆及守护所需落差仍保留。 |
| preset | `defense` 默认。另有 `civ`、`eco`。 |
| villageWidth | 所需最小平地宽度，6～⌊width/3⌋。默认 max(8,⌊width/11⌋)，文明改用 width/7。 |
| temperature | 可选整数 −40～50，单位 °C，默认使用群系气温。积雪另考虑局部海拔与温度噪声。 |

| 群系 | 地貌 |
|---|---|
| grassland 草原 | 缓丘、土层、草种和少量乔木 |
| forest 森林 | 较厚土壤、密集乔木和林下植物 |
| desert 沙漠 | 沙丘、沉积沙层和淡水绿洲 |
| tundra 雪原 | 冷丘、表层冰和积雪 |
| volcano 火山 | 山锥、露岩和洞底岩浆室 |
| coast 海岸 | 向海面倾降的大陆岸线、浅海架和咸水 |
| archipelago 群岛 | 一串高出海面的岛丘与岛间水道 |
| canyon 峡谷 | 分级崖壁和下切谷地 |

守护预设保留双向泄流坡和干燥村台。文明预设扩大默认建造平地并加厚土层。生态预设保留东侧自然地形并提高林木密度。三者均提供区域标注，守护的流路硬约束用于 defense。

## 区域、地层与水系

坐标原点在左上，y 向下。区域均为引擎可接受的 `{tag,x,y,w,h}` 矩形。

- `regions.village` 是平地上方 4 格高的村庄空间。脚下地面位于 y+h。
- `regions.spawns.left/right/top` 各有 `flood` 和 `lava` 两个出生区域。侧向洪水从山脊进入，熔岩从同坡靠近坡脚的出露口进入，减少长途冷却；上方两种灾难从村庄上空落下。下方为连续基岩。
- `regions.sources` 列出可取用的淡水矩形。咸水海域不计入村庄供水。
- `meta` 带有格式版本、标准化参数、淡水距离上限 waterReach、河道起止列 river.from/to 和洞室中心及名义半径 caves。区域标注与地图生成命令分开，供模式按需使用。

底部至少四行连续石层支撑上方地层。坡度允许时在岩面铺设土、沙及埋藏的沉积带，陡壁露岩。洞室开在厚岩层内，边界随层面弯曲，保留顶板和底部基岩。雨水的初始径流位于阶梯河床，顺坡汇入有堤肩的山湖；在这个有限水量系统中，河水会逐渐汇集。海岸和群岛另以共同海平面填充咸水。适宜的冷地表铺冰和雪，干燥岸边放置种子、植物或林木。

噪声用整数晶格哈希和 Q8 的三次平滑插值。局部布置使用独立的 xorshift32。生成过程不读取世界、系统时钟或宿主随机数，也不调用超越函数。缩略图由同一份命令重建。地图材质相同之外，测试还检查命令顺序、区域坐标和全部元数据。

## 守护约束如何检查

`src/gen/check.js` 提供静态检查 `checkDefenseMap(map)` 和真实物理检查 `checkMapStability(map)`。generateMap 在返回守护地图之前会对局部栅格执行同一套几何检查。批量验收还会单独从输出命令重建栅格，并对引擎实际执行 300 步。

1. 从命令重建格子，逐列检查村庄宽度、同高支撑和上方净空。
2. 从真实 WATER 格到村庄矩形取最近欧氏距离，上限为 ⌈width/5⌉+4 格，使用距离平方比较。
3. 分别检查六个出生区。从侧边出生点落到坡面上方，在相邻列横移后继续下落，全程要有空格可通行，禁止爬坡，到村庄须有净落差。熔岩路线连续同高平移最多四次。上方路线检查垂直净空。另有实际投放测试，每三步在源区以非覆盖笔刷补料，要求村庄内出现对应材料。
4. 创建同种子的引擎世界执行全部命令，保持结构力学开启，运行 300 个完整模拟步。每一步观察液体运动和原液体格占用，订阅 collapse 事件。结束后再次检查村庄、淡水和流路。

设 A 为总格数，L 为初始水、盐水、熔岩格数。以下任一项超过阈值即失败。

| 指标 | 最大允许值 |
|---|---|
| 累计坍塌事件格数；第 300 步原石格缺失数 | 两项各自 ≤ max(3, ⌊A/2000⌋) |
| 任一步液体移动次数，取引擎运动计数的逐步增量 | max(6, ⌈0.15L⌉) |
| 任一步原液体格腾空数 | max(4, ⌈0.20L⌉) |

凝固在原格的石头、冰按相变处理。少量河流入湖和颗粒调整允许发生。检查器的负例包括断开的坡道、丢失的淡水、悬空岩块和高处蓄水突然落下。

## 验证与新增群系

```sh
node tools/build.mjs
node tools/test.mjs --only=地图
node tools/mapgen.mjs audit
node tools/mapgen.mjs audit --size=422x246 --workers=5
node tools/mapgen.mjs bench
node tools/test.mjs
node tools/golden.mjs check
```

audit 默认对每个群系运行种子 0～999，交替使用 96×64 和 112×72，遍历 11 档起伏及不同村庄宽度。固定尺寸命令复用同一批种子。每张图均执行几何和 300 步实机物理检查；出现一张失败即返回非零状态，并输出可复现的种子和参数。可通过 `--seeds=N` 缩短本地迭代。bench 覆盖八个群系、三个用途和二十个种子，共 480 次 422×246 纯生成调用，单次超过或等于 200ms 会报告失败。

`tests/lib/mapgen-cases.js` 的 24 组固定输入跨全部群系与用途，含负种子、无符号边界和不同尺寸。Node 与浏览器分别对完整 JSON 输出计算摘要，并比对一个实际世界在第 0 / 300 步的哈希。浏览器使用 `?test=1`，本机静态服务器上的摘要算法为 SHA-256；没有 Web Crypto 的普通 HTTP 环境另有 FNV 校验。图册交互回归用例位于 `tests/browser/mapgen-gallery.pw.js`。

新增群系时，在 `src/gen/index.js` 的 mapgenBiomes 注册中文名称、默认温度、土层厚度、林木与植被密度。需要特殊地貌时，在自然高度场阶段添加对应剖面，然后复用村台、河湖、岩洞与地层步骤。为该群系写一个实际格子特征断言，跑种子扫描和尺寸边界测试，人工检查图册。若有意调整已发布的生成算法，更新 meta.version 和地图专用指纹，并重新做跨宿主比对。引擎黄金快照独立维护。

## 本轮实测

2026-11-20，Apple M3，Node 22.23.2。两次 audit 都使用 0～999 相同的种子编号，尺寸和村庄宽度随测试组变化。每张地图除了几何检查，还实际走完 300 步，共计 480 万个物理步。

实际投放测试另用 422×246 的种子 1，在六个起点以非覆盖笔刷持续注入水或熔岩，六组均进入村庄。生成性能以 `bench` 的 480 张地图计，Node 中位 0.33ms，最慢 5.48ms。该计时含命令打包与守护几何检查；300 步物理验收单独运行。
